# v0.5.0 — la validación fijada a un tag se puede leer, y firmar deja de ser copiar un sha

**Tag:** `v0.5.0` · **Fecha:** 2026-11-11

Esta release cierra dos correcciones: cómo se fija una versión al instalar, y el
trabajo de escribir una aprobación humana. No cambia ningún gate: la firma sigue
en `.yerro/approvals.yml`, la sigue escribiendo la persona y el alcance sigue
anclado al árbol.

## Qué cambia

### Instalación

- **Fijar una versión usa `#`, no `@`.** `npx skills add jeandybryan/yerro-sprints@v0.4.1`
  se lee como «la skill `v0.4.1`» y falla con `No matching skills found`. El ref va en el
  fragmento: `npx skills add 'jeandybryan/yerro-sprints#v0.4.1'`.
- `skills-lock.json` graba `"ref": "v0.4.1"`, así que `npx skills update` se queda en
  ese tag en vez de seguir `main`. Sin `#<ref>`, el lock queda sin ref.
- Documentado en `README.md` («Fijar una versión») y en las notas de `v0.4.1`, que
  mostraban el comando con `@`.

### Aprobación humana

- **`approvals.py --suggest <etapa>` imprime el bloque listo para pegar** con el
  `tree=` del snapshot actual, la fecha de hoy y el nombre que se pase
  (`--by "Tu Nombre"`). Ya no hay que leer el sha de la pasada y copiarlo sin cortarlo.
- **No escribe el archivo.** El helper solo imprime: el pegado en `.yerro/approvals.yml`
  lo hace la persona, igual que antes. El agente no gana ninguna forma de firmar.
- Avisa si ya hay una firma que cubre ese árbol, y rechaza una carpeta que no es
  `NN-nombre` en vez de imprimir el árbol vacío (`tree=4b825dc…`).
- Un campo escrito con guion bajo (`aprobado_por`) ya no se confunde con una clave
  desconocida: el error nombra la variante en vez de decir «falta aprobado-por».
- Caso `test_approvals.py` (7 comprobaciones), enganchado en CI; `EVALUATION.md` S64.

## Instalación

```bash
npx skills add 'jeandybryan/yerro-sprints#v0.5.0' \
  --skill '*' --agent cursor --copy --yes
```

En proyectos pnpm, `pnpm dlx skills add ...` con los mismos flags. Versiona
`.agents/skills/` y `skills-lock.json`.

## Cómo firmar una etapa

```bash
python3 .agents/skills/feature-stages/scripts/approvals.py . --suggest <etapa> --by "Tu Nombre"
```

Copia el bloque que imprime y pégalo en `.yerro/approvals.yml`. Esa es toda la
firma: el agente no puede escribirla.
