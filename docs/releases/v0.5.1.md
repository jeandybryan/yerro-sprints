# v0.5.1 — el README instala `v0.5.0` y enseña a firmar

**Tag:** `v0.5.1` · **Fecha:** 2026-11-11
Release de documentación. No cambia código, contrato ni gates: publica el
`README.md` corregido, que quedó fuera del árbol de `v0.5.0` y que ahora se
instala por `#v0.5.1`, y deja `v0.5.0` intacto como la release que cambió
comportamiento.

## Qué corrige

- **La instalación fijada apuntaba a `v0.4.1`.** «Fijar una versión» y el
  ejemplo de pnpm mostraban `#v0.4.1` y `"ref": "v0.4.1"` en el lock, dos
  versiones por detrás. El README instala `#v0.5.1` y el lock graba
  `"ref": "v0.5.1"`; desde ahí, `npx skills update` se queda en ese tag.
- **La aprobación humana no documentaba el helper.** «Aprobación humana» solo
  enseñaba el bloque YAML escrito a mano. Ahora explica que
  `approvals.py <repo> --suggest <etapa> --by "Tu Nombre"` imprime el bloque con
  el `tree=` del snapshot actual, que la persona lo pega, y que el campo escrito
  con guion bajo (`aprobado_por`) se detecta con un mensaje propio.
- «Actualización y versionado» enlaza la release vigente en vez de no declararla.

## Por qué una versión y no un `amend`

`v0.5.0` ya estaba publicada y su tag es inmutable por gobernanza
(`GOVERNANCE.md`: tag anotado `vX.Y.Z` por release, inmutable). Mover el tag o
reescribir su árbol habría cambiado lo que ya consume quien instaló desde él.
`v0.5.1` publica la corrección sin tocar `v0.5.0`.

## Nivel 4

No aplica: `v0.5.1` no modifica ninguna skill ni el contrato. La corrida de
nivel 4 que respalda el comportamiento vigente es la de `v0.5.0`
(`b92d85e`, 12/12), adjunta a esa release y versionada en
[`v0.5.0-REPORTE-nivel4.md`](v0.5.0-REPORTE-nivel4.md).

Los demás `test_*.py` no cambian entre `v0.5.0` y `v0.5.1`: el diff solo toca

## Instalación

```bash
npx skills add 'jeandybryan/yerro-sprints#v0.5.1' \
  --skill '*' --agent cursor --copy --yes
```

En proyectos pnpm, `pnpm dlx skills add ...` con los mismos flags. Versiona
`.agents/skills/` y `skills-lock.json`.

## Cómo firmar una etapa

```bash
python3 .agents/skills/feature-stages/scripts/approvals.py . --suggest <etapa> --by "Tu Nombre"
```

Copia el bloque que imprime y pégalo en `.yerro/approvals.yml`.
