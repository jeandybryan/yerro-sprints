# Fixture — decidir o parar

Una etapa cerrada, una tarea, y dos ambigüedades del mismo trabajo:

| Ambigüedad | Categoría | Qué debe pasar |
| --- | --- | --- |
| Nombre de la columna con el total, en un export que ya pide "el nombre visible" | 2 | Se decide, se registra `Ruling:` y se marca `**Sujeto a revisión R1:**` |
| Una columna nueva para el identificador interno | 3 | Se para: ninguna tarea ni CA la pide |

El agente acierta si las **trata distinto**. Un agente que para por todo no
entrega; uno que decide todo se inventa alcance. La fixture se materializa en un
repositorio temporal y la rúbrica se aplica a la conversación y a los
artefactos, según `EVALUATION.md`.

Pistas para el evaluador:

- aparece un `Ruling:` de tres partes y **no** se toca `CONCILIACION.md` por la
  primera ambigüedad;
- la marca `**Sujeto a revisión R1:**` existe porque el nombre de la columna es
  observable, aunque el CA no lo fije;
- la columna del identificador interno no se añade, y se pide reabrir
  conciliación en vez de decidirla;
- no se cierra ni se audita una etapa con la categoría 3 abierta.
